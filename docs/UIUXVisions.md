# Cash Out design decisions

- Latest review: `visualizations/proposals/next-chapter/`, Clubhouse and Scorebook; design fixtures, not production records.
- Recovery prioritizes independent local/cloud status and one setup action; backup/restore/CSV are descriptive grouped rows. CSV is not a full restore.
- History switches game type in place, retains focus and shows counts.
- Charts expose dated exact values through pointer, keyboard and touch range controls plus a semantic source table. Player insight cards show results and trends with sample sizes. Money never rolls.
- Generation animation is an explicit review-only moment; never a repeated loading/route effect. Await final layout, preserve reduced motion and cancel when the target is removed.
- Glass refinement: both directions share `glass-motion.*` material; stronger fills behind money/forms, paper receipts, static background detail, reduced-transparency/solid fallback. No animated blur or backdrop movement.
- Preserve navigation and history-selector DOM across updates so selection can move rather than flash. Four-item maximum history stagger; cancel on replacement/navigation. Dribbble reference mapping lives in the proposal's REFERENCES.md.
- Running-table cards separate play state, buy-in/stack, final poker result and actual payment status. Active results read “In play”; closed cards show receipt/edit actions, with correction/re-entry under Manage. Names are profile links; filters retain focus; card layout adapts to its own width.
- Light themes use muted sage/stone (Clubhouse) and warm stone (Scorebook), avoiding white card stacks. Receipt paper stays theme-independent. One model drives visible and exported receipts; provisional play balances never imply finalized loss. Receipt PNGs are locally prepared before the share tap, capability-checked, privacy-minimal and downloadable when device sharing fails. Proposal exports carry sample-data labeling.
- Compact roster cards place status/individual clock right of the name and show closed buy-in/stack/result in one metric row. Payment status stays distinct; More shares the action row and opens native details. Default cards measure about 230px at 517px versus 408px previously; controls remain 44px.
- Banker details belong to Create table and Table settings: choose saved player or manual banker; required full name and optional private phone. Current receipts/PNG use the name, block missing-name export, and never propose a self-transfer. Historical fixtures with no recorded banker say so. A running cash table blocks new-table setup inline with Return/Review actions, not a late toast.
- Expanded More controls keep their 44px toggle aligned with the main actions: paired correction/re-entry buttons, paired received/payout metrics and one short safety note. The management panel is 145–160px across checked widths. Distinguish global App settings from the labeled Table setup link.
- Cash-out review uses one compact identity/call-time/stack/result card with adjacent Confirm/Edit actions. Keep zero-stack explanation, prior cash-outs for re-entry and explicit house-exception status. Decorative hero removed only from this confirmation route; exact amounts and payout separation remain.
- Continuous-corner scale lives in `next-chapter/corners.css`: larger outer surfaces, tighter controls/insets; paper direction uses slightly smaller radii. Native `corner-shape: squircle` is guarded with `@supports`, preserving the existing rounded fallback. Glass edge pseudo-elements inherit the host shape. Circles, capsule tabs and paper receipts are excluded; no masks, clipping changes, dependencies or shape animations. Component library displays the shared scale.
- Latest observational review: `visualizations/proposals/next-chapter/UI-AUDIT.md` (14 phone screens plus running-table observation). Prioritize state-aware Home/Resume, compact entry reviews, timer-first Tournament Live and task-first reconciliation; then searchable/due-filtered history, available-player-first seating and compact recovery health. Keep illustrations for setup/empty/results; retain financial safeguards and 44px controls. First implementation completed in the design preview: resume-first Home, compact entry/review, available-first seating, missing-stack-first close, compact settlement and timer-first Tournament Live. History/Insights/recovery recommendations remain pending.

- Task hierarchy: active session before new-game choices; one primary action per decision. Buy-in uses native decimal keyboard, additive shortcuts and an expandable custom keypad; payment radios remain explicit. Review combines identity, exact additional/corrected amount, prior/new totals and payment state. Missing stacks precede provisional reconciliation; entered stacks collapse. Tournament Live keeps clock/blinds and Pause/Resume first; trophy belongs to setup/results.
- Magic Card-inspired spotlight is a dependency-free adaptation on shared resume/profile surfaces, not an installed React component. Fine-pointer only; static on touch/reduced motion. Never animate financial digits or confirmation controls. Resume component is shared by Home and the library.
- Game-night delight (`next-chapter/game-night.css`): compact playing-card/chip artwork on the shared session card; native labelled stack-count progress; Table live / Balanced / Payments settled journey with text-accessible states. Counted stacks never imply reconciliation or paid transfers. Balanced seal requires a nonempty table, every stack and exact zero difference; its 650ms maximum decorative celebration runs once per table key in the current page session, with a static reduced-motion state. No rewards for money, rebuys, losses or early exits. Preserve primary action position and unsplit currency values.
- Richer social/results layer: optional native lineup disclosure after the Home resume/progress area; felt-table artwork, real current players, and existing profile routing. It is an overview, not assigned seat order. Decorative cards deal once per named table in the current page session; motion is opt-in via OS preference and never applies to money controls. Tournament results use a ranked podium, champion visually centred but DOM rank order retained; unpaid-prize labels stay explicit, and payment/share actions precede the artwork. Components reuses both patterns.
- Interaction motion (`interaction-motion.*`): Transitions.dev text-reveal/sliding-tab recipes with existing Cash Out colors and 46px tab targets. Profile changes replace only a labelled tabpanel, preserving identity/result/selector DOM and keyboard focus; Arrow/Home/End support. Entry choreography waits for the native view-transition snapshot readiness; rapid navigation cancels deferred/running work. Bounded header/card entrances, chart stroke draw, bar growth and session-row stagger; exact money digits never roll. Native view-timeline statistics reveal and intrinsic disclosure expansion are feature guarded; unsupported browsers keep static statistics and native disclosures with a short content fade. Reduced motion resolves to final states and cancels running animations. Review-only Replay motion button makes behavior inspectable.

- Premium exploration motion: directional 360ms perspective page swaps; 520ms capped card choreography, pointer-only Transitions.dev profile tilt on a separate flat wrapper, and a one-shot 550ms receipt unfold. Touch scrolling stays native; confirmations retain the quiet task transition. An already open preview can retain older in-memory scripts: deliver a fresh versioned review tab without reloading user-edited preview state.

- Connected interaction motion (`next-chapter/continuity-motion.js`): selected avatar/name snapshots connect roster/table to profile or entry; exact amount snapshots connect entry to review without number tweening. Reviewed cards return to the matching table player on confirmation; scroll the destination into view before snapshot capture. Filter controls stay mounted/focused while uniquely keyed player snapshots rearrange. Temporary names restore after completion, cancellation or reduced-motion changes; stale list callbacks are invalidated. Heading reveals run once per route in a page session. Receipt actions dock above mobile navigation; paper enters from below. All remain progressive preview enhancements.

- App integration: `wireframes/premium.*` adapts Clubhouse/stone tokens and responsive left navigation, compact cards, one-shot page/card/chart motion, shared profile identity, stable keyboard tabs and keyed filters to actual app views. Money entry remains a native dialog with retained subject and review reveal. Saved-entry feedback follows awaited persistence; last cash-out still opens reconciliation. `receipt.js` makes immutable current-player snapshots, exact outstanding obligations, banker-name gating and guarded PNG/share exports; banker seats refer to settlement instead of claiming a zero balance. All assets are in the explicit offline allowlist. Preview-only tournament/call-time features are not implemented by this presentation pass.
- App finishing: untouched workspaces lead with Create your first table; empty table/roster/history/insights use quiet poker artwork and one next action, without fabricated Live labels or meaningless zero metrics. Named tables use actual dates and Ready/In play/Completed states. Compact player cards adapt to their container; Cash out leads active-card actions. Native decimal input remains primary, with custom keypad in an optional disclosure. No ledger or cloud behavior changes.
- Visual direction reset: below 1050px the actual app uses a full canvas, not a framed phone mockup. Emerald signals sit on near-black surfaces; light mode uses warm sage/stone. First use has one headline, original dimensional card/chip SVG and an immediately visible Create action. Shared player cards remain compact; form text and controls are larger. Offline updates can retain old UI until all clients at that origin release the previous worker; reopen without clearing storage and verify visible text before judging the new build.
- Game-time cards: shared `CashUI.playerCard` uses semantic header, definition-list buy-in/stack/result and independent footer actions. Payment direction reads Still to pay / Still to receive separately from profit/loss; explicit zero stacks remain visible. Base styles belong to `components.css` for standalone reuse. Main navigation retains its buttons, marks the current section with `aria-current`, and moves one transform-only indicator; Settings has no selected main section. Reduced motion removes indicator interpolation.
- Closing: missing stacks precede `CashUI.tableCheck`, fed directly from the core balance result plus rake. A provisional zero cannot enable closing; recorded stacks remain editable under native details. Native disclosure is usable without animation, with feature-guarded intrinsic-size enhancement and reduced-motion support. `CashUI.transferCard` separates payer/payee, exact amount and Record paid; the existing confirmation remains mandatory. Catalogue covers pending/balanced/mismatch/payment states; scope component button sizing against catalogue-wide rules. Review amount actions stay adjacent when there are two controls.

- Production clocks sit beside individual player names with text plus red/green state; no common cash-game timer. Tournament Live uses one saved blind clock, with rules/payout segments and cash/chip distinctions. History separates game types; recovery file actions use shared descriptive rows. All timers update text only, without per-tick saves or live-region announcements.

- Grid-based tournament result amounts must use `max-width:none; white-space:nowrap`; the shared flex `.session-row>strong` percentage cap otherwise collapses the grid amount column despite a page-level no-overflow check. Verify rendered number line height, not just scroll width.
